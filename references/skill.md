# skill.md — 技能学习分析框架

> 适用：语言学习、乐器学习、编程学习、绘画学习、健身训练、烹饪学习、手工技艺、运动技能等技能教程/教材。

---

## 体裁特征与识别信号

### 典型文本特征
- **结构**：知识单元→技能讲解→示例演示→练习任务
- **语言**：指导性、实用性、多用步骤说明和示例
- **篇幅**：差异大（入门几百页到教材系列）
- **标志词**："第一步""练习""注意""技巧""掌握""入门""进阶""实战"

### 常见子类型
- 语言学习（《新概念英语》《赖世雄美语》《大家的日语》）
- 编程/计算机技术（《Python编程从入门到实践》《算法导论》《代码大全》）
- 乐器学习（《吉他自学三月通》《拜厄钢琴基本教程》）
- 绘画/设计（《伯里曼人体结构》《写给大家看的设计书》）
- 健身/运动（《斯瓦辛格健身全书》《跑步圣经》）
- 烹饪/手工（《随园食单》《木工基础》）
- 职场技能（《PPT设计思维》《Excel数据分析》）

### 易混淆体裁及区分要点
- vs **成长实用类**：技能学习侧重"学会做一件事"，成长类侧重"提升认知/习惯"。若书籍同时涉及成长与技能（如《如何高效学习》《认知天性》），按 `_shared.md` 的"特殊情形"规则让用户选择
- vs **教材/百科**：技能学习强调动手实践，教材侧重系统知识
- vs **自然科学**：编程等计算机技术看似科学，但学习时侧重实操技能

## 分析维度

> 📌 **核心/扩展区分**：标注 ⭐ 为核心维度（精读必做），其余为扩展维度（深度分析时补充）。

本体裁采用 **"懂→会→用"闭环**，从"理解知识"到"掌握技能"到"真实应用"形成完整链路。

### 维度一：书籍定位与学习者匹配 ⭐

**分析问题**：这本书"对我学这门技能有啥用"？

**执行动作**：
- 技能领域锚定 + 学习阶段定位（入门/进阶/专精）
- 作者背景与技能教学能力关联
- 这本书解决的核心学习卡点
- 精准学习者画像（适合谁、不适合谁）

### 维度二：技能地图与学习路径 ⭐

**分析问题**：这门技能由哪些能力构成？学习顺序怎么安排？

**执行动作**：
- 拆解核心技能点（而非知识点）
- 技能依赖关系（哪些要先学、哪些可以并行）
- 书中学习路径评估（顺序合理吗？有遗漏吗？）
- 绘制"从菜鸟到能干活"的路线图

**输出格式**：

```markdown
### 核心技能点
| 技能点 | 核心内容 | 难度 | 前置要求 |
|--------|----------|------|----------|
| ... | ... | ★★ | 无 |
| ... | ... | ★★★ | ... |

### 技能依赖关系
[前置技能 → 进阶技能 → 高级技能]
```

### 维度三：核心知识单元萃取 ⭐

**分析问题**：这门技能涉及哪些"要懂的东西"？把书中的核心知识拆成"小模块"，每个模块都要"能看懂、能讲清"。

**执行动作**：每个知识单元需包含：

| 元素 | 说明 |
|------|------|
| 核心概念 | 一句话精准概括"要懂什么" |
| 书籍依据 | 引用原文或精炼概括（注明章节/页码） |
| 理解卡点 | 这个概念最容易误解/卡住的地方 |
| 应用场景 | 这个知识在什么情境下会被用到 |
| 提醒 | 易踩坑的理解误区 |

### 维度四：核心技能单元萃取 ⭐

**分析问题**：这门技能包含哪些"要会做的事"？把书中的核心技能拆成"小模块"，每个模块都要"能看懂、能上手"。

**执行动作**：每个技能单元需包含：

| 元素 | 说明 |
|------|------|
| 技能要点 | 一句话精准概括"要能做到什么" |
| 书籍依据 | 引用原文或精炼概括（注明章节/页码） |
| 学习卡点 | 学会这个技能最容易卡住的地方 |
| 场景应用 | 这个技能在什么情境下用得上 |
| 提醒 | 易踩坑的使用误区 |

### 维度五：知识→技能的转化逻辑 ⭐

**分析问题**：不仅要知道"懂什么"和"会什么"，还要搞懂"懂了怎么变成会了"。

**执行动作**：
- 哪些知识是哪些技能的前置？
- 知识如何指导实践？（理论→操作的桥梁）
- 有没有"懂了但不会用"的风险点？

### 维度六：刻意练习设计 ⭐

**分析问题**：练习设计是否有效？我该怎么练？

**执行动作**：
- 练习数量与难度梯度评估
- 练习类型分析（模仿/变式/综合/实战）
- 反馈机制：如何判断做得对不对？
- 纠错设计：常见错误是否指出来？如何纠正？
- **补充建议**：书中练习不足时，给出补充练习方案

**输出格式**：

```markdown
### 练习设计
| 类型 | 数量 | 难度梯度 | 反馈机制 | 纠错设计 |
|------|------|----------|----------|----------|
| 模仿练习 | ... | ... | ... | ... |
| 变式练习 | ... | ... | ... | ... |
| 综合练习 | ... | ... | ... | ... |
| 实战练习 | ... | ... | ... | ... |

### 补充建议
[书中练习不足时的补充练习方案]
```

### 维度七：场景化应用迁移 ⭐

**分析问题**：学完能用在哪些真实场景？把书中的技能和自己的实际需求绑在一起，才算真正"学到手"。

**执行动作**：
- 真实场景映射（职场/生活/兴趣场景）
- 场景化小任务设计（今天就能做的一个小练习）
- 学习成果可视化（学会后能产出什么）

### 维度八：学习计划与行动清单 ⭐

**分析问题**：知识不落地就是"空话"，这一步帮你把它变成可执行的行动。

**执行动作**：
- 量化行动清单（若干条，每条明确时间限制+具体内容+完成标志）
- 里程碑设计（什么时候应该达到什么水平）
- 预判阻碍与应对

### 维度九：反常识学习观 ⭐

**分析问题**：这本书有没有颠覆你以往学习直觉的观点？这些"反常识"往往是高效学习的突破口。

**执行动作**：每个反常识观点需补充：
1. 认知调整：用一句话说服自己接受这个"反常识"
2. 小步尝试：今天可做的 1 个小改变
3. 反馈优化：判断改变是否有效的标准
4. 惯性对抗方法：如何克服旧习惯的阻力

**示例**：
- 反常识："学编程不应该从头看书，而应该先动手写代码"
- 认知调整："编程是肌肉记忆，不是阅读理解"
- 小步尝试："今天就用刚学的语法写一个小程序"
- 反馈优化："能独立写出 20 行可运行代码就算有效"
- 惯性对抗："想看书的时候，先写 10 分钟代码再看"

### 维度十：常见错误与避坑（扩展）

**分析问题**：学习这门技能容易踩哪些坑？

**执行动作**：
- 常见错误：初学者最容易犯的错误
- 避坑指南：如何避免这些错误？
- 错误纠正：犯了错如何纠正？
- 警示信号：什么信号表明学习方法有问题？

### 维度十一：终极凝结 ⭐

**分析问题**：用一句话总结全书最核心、最值得你记住的学习要领。

**执行动作**：这句话要同时包含"核心技能观"和"行动指引"。

## 执行步骤

```
Step 1: 通读全书，拆解知识单元和技能单元
Step 2: 绘制技能地图和依赖关系
Step 3: 萃取核心知识单元
Step 4: 萃取核心技能单元
Step 5: 分析知识→技能的转化逻辑
Step 6: 评估练习体系
Step 7: 提炼反常识学习观
Step 8: 设计场景化应用迁移
Step 9: 制定学习计划与行动清单
Step 10: 梳理常见错误与避坑
Step 11: 整合输出，按模板交付
```

## 语气风格规范

### 称呼方式
- 实用导向、有教学经验
- 像一个资深教练/导师，既懂理论又懂实操
- 称呼读者为"你"，拉近距离，避免说教感

### 句式特征
- 每一步以"提示"开头（给出这一步的核心提醒）
- 涉及操作建议时，用"建议""可以试试""不妨"等协商语气
- 涉及常见错误时，用"提醒""注意""这个地方容易踩坑"等警示语气
- 多用具体例子替代抽象描述，宁可少而精不要多而浅

### 示范句式
- "提示：先搞清楚这门技能的'技能地图'，避免一上来就盲目练习。"
- "这本书的技能地图可以概括为……"
- "从技能学习的角度来看，这一章节的设计精妙之处在于……"
- "值得注意的是，这一阶段的练习量可能不足，建议补充……"
- "提醒：这个地方容易踩坑，咱们得多留个心眼。"
- "建议你先花 X 分钟做个小测试，看看自己目前的水平，再决定从哪个阶段开始。"

### 禁忌用语
- 不要居高临下地说"你应该""你必须"
- 不要空泛地说"这本书很有价值""这是一本好书"
- 不要把技能教程当成文学作品分析（情节、修辞、意境等不是重点）
- 不要忽视练习体系的重要性（技能学习的核心是"学会做"）
- 不要把学习分析变成内容摘要（"这本书讲了……"不等于分析）
- 不要脱离原文的主观臆断（所有分析必须锚定原文）

## 常见陷阱

1. **文学化分析**：把技能教程当成文学作品分析（纠结情节、修辞、意境）→ 技能学习的核心是"学会做"，分析重点是知识体系和练习设计
2. **忽视练习**：只分析知识不分析练习 → 练习体系是技能学习的核心，必须逐层分析数量/难度/类型/反馈
3. **混淆"懂"和"会"**：把知识单元和技能单元混在一起 → 知识聚焦"理解"，技能聚焦"操作"，分开萃取更清晰
4. **忽视转化**：只列知识和技能，不分析怎么从懂变成会 → 维度五专门解决"知识→技能的桥梁"问题
5. **内容摘要**：变成"这本书讲了……"的罗列 → 分析应有洞见，要揭示"为什么这样设计""哪里好哪里不好"
6. **脱离原文**：用自己对技能的理解替代书中内容 → 所有分析必须锚定原文，引用章节/页码
7. **风格漂移**：从"陪练语气"漂移成"学术语气"或"评论语气" → 保持实用导向、有教学经验的导师口吻

---

*技能学习分析的关键是：在"懂"与"会"之间架桥——既理解知识体系，又掌握操作技能，最终让改变真实发生。*
