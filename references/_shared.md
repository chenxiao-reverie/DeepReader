# _shared.md — 跨体裁共享规范

本文件定义所有体裁复用的基础设施：文本预处理、输出模板框架、质量验证、边界情况处理、路由表、触发词、跨体裁规则。
各体裁文件（`references/*.md`）在执行分析前应先加载本文件的预处理规范，在输出时遵循本文件的模板框架。

---

## 一、文本预处理

### 1.1 输入读取

根据用户输入类型选用对应方式：

| 输入类型 | 处理方式 |
|----------|----------|
| `.txt` / `.md` 文件 | `read` 工具读取全文 |
| `.epub` | 调用 epub skill 提取正文段落 |
| `.pdf` | 调用 pdf skill `extract_text` |
| URL | `web_fetch` 获取内容 |
| 粘贴文本 | 直接使用 |

> ⚠️ EPUB/PDF 是二进制文件，**必须用对应 skill 工具提取文字后再分析**，不能把文件路径当文本传入。

### 1.2 章节切分

按优先级尝试以下策略，记录使用哪种：

| 策略 | 匹配特征 | 正则/方法 |
|------|----------|-----------|
| **A** - 标准格式 | `第X章` 或 `第X章 标题` | `第[\d零一二三四五六七八九十百千]+章` |
| **B** - 数字编号 | 独立行数字 | `^\s*\d+\s*$` |
| **C** - POV切换 | 角色名小标题 | 按POV名称变化分割 |
| **D** - 卷部结构 | `第X卷` + `第Y章` 双层 | 先按卷切，再按章切 |

**异常处理**：
- 全文 <5000字且无任何规则匹配 → 标记"[短篇免切分]"，整篇作为一个单元
- 某章 >20000字 → 尝试按空行二次切分
- 某章 <300字 → 合并到上一章（防止碎片化）
- 古文/半文言 → 降低置信度，标注"[古文-需人工复核]"

### 1.3 元信息提取

从文本中提取以下元信息：

```json
{
  "title": "书名/文本名",
  "author": "作者（如可识别）",
  "type": "体裁类型",
  "total_words": "估算总字数",
  "total_chapters": "章节数（如适用）",
  "segmentation_strategy": "使用的切分策略A/B/C/D",
  "language": "现代汉语/古文/翻译作品/外文",
  "structure_features": ["结构特征列表"]
}
```

## 二、长文本分块策略

超出模型上下文窗口的长文本，采用分块-并行分析-合并方案。

### 分块阈值

| 总字数 | 策略 |
|--------|------|
| <30万字 | 全文一次加载 |
| 30-80万字 | 按卷/部拆分 |
| >80万字 | 强制分块，每块 ≤8万字 |

### 分块方式

优先使用结构分界，其次用固定大小：

1. **按卷/部**：以"第X卷""第一卷""Part X"为界，每卷独立分析
2. **按POV**：多POV文本按主角视角分组
3. **固定窗口**：每80章一块，相邻块重叠3章（保证边界不遗漏）

### 合并步骤

1. **实体去重**：合并各块实体列表，按名称/别名匹配去重
2. **关系拼接**：跨块的实体关系用全局章节号重新标注
3. **伏笔/线索跨越**：埋设在前块、照应在后块的线索，在后块分析完成后回溯补全
4. **节点校准**：确保全局章节号统一

### 用户交互

分块分析前告知用户：
- "本书约X万字，将分为N块分析，预计需要Y分钟"
- 每块完成后报告进度："第N块分析完成 (N/M)"
- 合并完成后统一交付结果

## 四、分层分析方案

为缓解"实操性与深度的矛盾"，提供三档分析深度，用户可根据时间和目的选择：

| 层次 | 时间投入 | 覆盖内容 | 适用场景 |
|------|----------|----------|----------|
| **5分钟速览** | 约5分钟 | 核心摘要 + 关键洞察 + 一句话总结 | 快速了解一本书值不值得读 |
| **30分钟精读** | 约30分钟 | 上述 + 体裁专属分析（核心维度） + 金句 | 日常阅读，掌握核心内容 |
| **3小时深度分析** | 约3小时 | 全部维度（含扩展维度） + 读者反应日志 + 批判性审视 + 知识迁移 | 深度阅读/写书评/准备分享 |

### 分层执行规则

1. **默认档位**：未指定时按"30分钟精读"执行
2. **用户指定**：用户说"快速看看"→速览；"深度分析"/"榨干"→深度
3. **核心/扩展区分**：每个体裁需标注"核心维度"和"扩展维度"，精读只做核心，深度全做
4. **时间估算**：分析前告知用户预计时间，让用户确认

## 五、质量验证清单

分析完成后自检以下项目：

| 检查项 | 通过标准 | 不通过时处理 |
|--------|----------|-------------|
| 核心内容覆盖率 | 主要观点/情节/人物无遗漏 | 补充分析 |
| 原文锚定 | 每个论点有原文依据 | 标注"【推断】" |
| 体裁适配 | 使用了该体裁专属分析维度 | 重新检查路由 |
| 逻辑自洽 | 分析结论前后一致 | 修正矛盾项 |
| 置信度标注 | 低置信度项已标注 | 补充标注"【需人工复核】" |
| 输出完整性 | 包含所有必要章节 | 补充缺失章节 |

### 通用质量标准

- **忠实原文**：所有分析必须锚定原文，拒绝主观编造
- **深度可读**：深入分析但语言通俗，宁可少而精不要多而浅
- **体裁适配**：不同体裁用不同分析框架，拒绝一刀切
- **用户主权**：跨体裁时让用户选择方向，不武断判断

## 六、边界情况处理

### 6.1 文本相关

| 情况 | 处理 |
|------|------|
| 短篇 <5000字 | 标记"[短篇模式]"，简化分析，聚焦核心维度 |
| 无章节标识 | 按空行分段，每段约3000-5000字，标记策略"C无章节" |
| 古文/半文言 | 人物识别降低置信度，标注"[古文-需人工复核]" |
| 第一人称 | POV恒定，跳过POV分析 |
| 对话体/剧本 | 按场次切分，角色直接从对话前缀提取 |
| 连载中（未完结） | 只分析已有内容，所有结论标注"[当前进度]" |
| 翻译作品 | 标注原文语言，注意文化差异可能影响分析 |

### 6.2 体裁相关

| 情况 | 处理 |
|------|------|
| 现实题材无奇幻元素 | 跳过"力量体系"等不相关维度 |
| 短篇无多线叙事 | 跳过多线分析 |
| 纯抒情无叙事 | 聚焦情感/意象/语言维度 |
| 体裁边界模糊 | 展示候选让用户选择 |

### 6.3 质量相关

| 情况 | 处理 |
|------|------|
| 某结论置信度低 | 标注"[低置信度-需人工确认]"，不强制拟合 |
| 信息识别不完整 | 标注遗漏可能，允许用户手动补充 |
| 分析不通过 | 标注失败项，提示用户可能原因 |
| 章节切分失败 | 退化为全文分析模式，提示用户手动提供章节划分 |

### 6.4 用户交互

| 情况 | 处理 |
|------|------|
| 用户纠正错误结果 | 接受修正，局部重新分析（不全量重跑） |
| 用户提供额外信息 | 合并到现有分析结果，标注"[用户补充]" |
| 用户要求对比两本 | 分别分析，做对比总结 |
| 用户取消分析 | 保存已完成的部分结果，不要丢弃 |

## 七、数据传递原则

1. **上下文传递优先**：分析过程中数据通过上下文传递，不强制写文件
2. **最终交付时写文件**：所有分析完成后统一写入输出
3. **全局标识符**：人物 ID 格式 `C001`、伏笔 ID 格式 `F001`、关系 ID 格式 `R001`
4. **避免重复计算**：上游已生成的数据，下游直接复用

## 九、跨体裁处理规则

当检测到内容涉及多个主题时，向用户展示候选方向：

```
我检测到这本书涉及以下几个方向：

1️⃣ 【视角A】（占比约X%）— 该视角下的核心分析维度
2️⃣ 【视角B】（占比约Y%）— 该视角下的核心分析维度
3️⃣ 【视角C】（占比约Z%）— 该视角下的核心分析维度

你想从哪个角度深入分析？也可以说"全部都要"，我会按顺序逐一拆解。
```

### 处理规则

1. **主次型**（如《人类简史》主历史+辅生物/心理）→ 以主要体裁框架为主，在相关维度融入次要视角
2. **并列型**（如《苏菲的世界》哲学+小说）→ 提供选项让用户选择优先角度
3. **融合型**（如《百年孤独》小说+神话+历史）→ 以主体裁框架为主，在世界观/主题维度融入其他分析
4. **用户主权**：始终让用户有选择权，不武断替用户决定
